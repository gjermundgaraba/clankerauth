# 0.23.0 — Breaking: errors that name what failed, and effect-actions 0.17.0

Administration's error responses change shape, the issuer no longer upgrades databases created
before 0.16.0, and every package moves to effect-actions 0.17.0. Upgrade the issuer and the
`clankerauth` command together: a 0.22 command reads a 0.23 issuer's refusals as unknown
failures. Resource servers on SDK 0.22 verify against a 0.23 issuer unchanged, and the reverse.

## Upgrading

The issuer no longer carries the data upgrades for databases created before 0.16.0. Before
moving an older issuer to 0.23.0, start it once on 0.22.x, which applies them, and stop it.
A database created by 0.16.0 or later needs nothing.

An application that uses the SDK's `/session` or `/effect-actions` entry points installs
`@gjermundgaraba/effect-actions` `0.17.0` with SDK 0.23.0. Two changes of its own may reach
application code:

- An action's span now covers authorization and cleanup as well as the handler, so dashboards
  that read action duration as handler time need a named span inside the handler.
- `ActionMcp.McpCallError` says why in a tagged `reason` (`StatusError`, `ProtocolError`,
  `NoReply`, `UndeclaredError`, `NoStructuredContent`); match on `error.reason._tag` where code
  matched its message.

## Administration errors

Each action declares only the failures it can produce, and each failure names its subject and
carries its sentence as `message`, over HTTP and as MCP tool errors alike.

| 0.22                                                                          | 0.23                                                      |
| ----------------------------------------------------------------------------- | --------------------------------------------------------- |
| `NotFound` (404), `error: "Client not found"`                                 | `ClientNotFound` (404), `clientId`, `message`             |
| `NotFound` (404) from a resource or key                                       | `ResourceNotFound` `identifier`, `ApiKeyNotFound` `keyId` |
| `Conflict` (409), `error: "Setup already completed"`                          | `OwnerExists` (409), `message`                            |
| `BadRequest` (400) for client access on an automatic client                   | `ClientIsAutomatic` (409), `clientId`, `message`          |
| `Forbidden` (403) editing or rotating an automatic client                     | `ClientIsAutomatic` (409)                                 |
| `BadRequest` (400) from the provider's own rules                              | `ProviderRefused` (400), `message`                        |
| `BadRequest` (400), an unreadable body on forward auth or the provider bridge | `UnreadableRequest` (400), `message`                      |
| `InternalServerError`, `ServiceUnavailable`, `error`                          | the same tags, `message`                                  |
| `TooManyRequests` (429)                                                       | removed                                                   |

Setup's input schema enforces the password length (8 to 128 characters) and a non-blank email,
so a bad one answers `InvalidInput` naming the field. The OpenAPI document's API-key schema is
`ApiKey`, formerly `MachineKey`.

## SDK

- The optional `@gjermundgaraba/effect-actions` peer is `^0.17.0`.
- `@gjermundgaraba/clankerauth-sdk/key-list` exports `keyPrefix`, the prefix every API key
  begins with.
- `@gjermundgaraba/clankerauth-sdk/session` exports `signOutPath`, the path `signOutUrl` builds on,
  and `returnToParameter`, the query parameter that names where the issuer sends the owner next.

## Issuer

- A resource write checks its input before it opens a provider session, so refused input opens
  none.
- The consent page separates the resource codes it lists, as the dashboard does.
- The setup page checks only that the confirmation matches; a field the issuer rejects is
  named under it with the issuer's own sentence.
- Tracing spans are named for the issuer's services, such as `Clients.list`,
  `ResourceCatalog.get` and `OwnerAccount.providerSession`.
- Forward auth answers a provider failure it does not expect, such as a 401 or 403, as
  `InternalServerError` (500), where it answered `Forbidden` (403).

## Development package and CLI

- The development package embeds the 0.23.0 server through its one public entry; its API is
  unchanged.
- The CLI's commands are unchanged.
- Both are built on effect-actions 0.17.0.
