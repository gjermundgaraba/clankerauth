# 0.31.0 — Breaking: redacted provider headers, trimming contract schemas, `ProviderUnavailable.of`, and tagged development-issuer errors

Breaking for TypeScript code that implements or reads the administration contract's `Owner`, that encodes resource or key input through the contract, that builds `ProviderUnavailable` with a cause, that calls the SDK's `Credentials.list()`, or that catches or fakes what `@gjermundgaraba/clankerauth-dev` returns. The database, the configuration, the issuer's HTTP and MCP wire forms and the SDK's verification are as in 0.30.0, so an application on SDK 0.30.0 verifies against a 0.31.0 issuer and the reverse. Every package and the server go to 0.31.0 to keep one version across the release.

## Upgrading

1. **Provider headers.** `Owner.providerHeaders` yields `Redacted<Headers>`, formerly `Headers`. Unwrap it with `Redacted.value` where the provider takes it, and build it with `Redacted.make`.
2. **Trimming input schemas.** `ResourceInput`'s `identifier`, `name` and `scopes`, and the key name of `ApiKeyInput` and `ApiKeyUpdate`, are `Schema.Trim`: decoding trims them, and encoding refuses a value with surrounding whitespace. A client that encodes through the contract trims first, as the dashboard does. A request sent as JSON is unaffected: the issuer trims it on decoding, as it trimmed before.
3. **`ProviderUnavailable` with a cause.** Its constructor takes only `{ operation }`. Build one with a diagnostic cause as `ProviderUnavailable.of(operation, cause)`, formerly `new ProviderUnavailable({ operation, cause })`. The cause stays non-enumerable and off the wire.
4. **`Credentials.list` is an Effect.** The `/credentials` entry's `list` is the Effect itself, formerly a function returning it: write `yield* Credentials.list` for `yield* Credentials.list()`.
5. **Development issuer errors.** `startDisposableIssuer` and a refused `apiKey` reject with `ProvisioningError`, and a refused `ownerSession` or `ownerToken` with `ForwardAuthError`, formerly a plain `Error` with the same message. Both are exported, and each one's `_tag` is its name.
6. **Development issuer type.** `DisposableIssuer` declares `apiKey`, `ownerSession`, `ownerToken` and `close` as properties rather than methods, so a hand-written stand-in is checked against them strictly rather than bivariantly.

## Administration contract

- `Owner.providerHeaders` is `Effect<Redacted<Headers>, InternalServerError, Scope>`.
- `ResourceInput` and the key name trim on decoding. A resource's name and a key's name need one character after trimming, and a key's name at most 100 after trimming. Their JSON Schema, in the OpenAPI document and the MCP tool schemas, describes the wire form, a plain string, so it no longer carries the non-space pattern of a name or the pattern of a scope. The issuer refuses the same input as before, with the same messages.

## SDK

- `ProviderUnavailable.of(operation, cause)` builds the error with a diagnostic cause. The constructor takes `{ operation }`.
- `/credentials`' `list` is an Effect value rather than a function.
- The `/testing` entry's `startFakeIssuer` throws a `TypeError` when it cannot bind a port, formerly a plain `Error`.
- The `/effect-actions` entry's `Resource.verificationDeadline` is the five seconds a `Resource` gives each verification before failing it as `ProviderUnavailable`.

## Issuer

- Built on the new contract. It no longer trims resource and key input itself, since the contract's decoding does.

## CLI and development package

- Built on the new contract.
- `startDisposableIssuer` decodes its `resources` through the contract's `ResourceInput`, so their names and scopes are trimmed and checked as the dashboard's are. An invalid one rejects the start with `ProvisioningError`.
- `ProvisioningError` and `ForwardAuthError` are exported from the package root.
- The `/edge` entry's `reserveLoopbackPort` throws a `TypeError` when it cannot bind a port, formerly a plain `Error`.
