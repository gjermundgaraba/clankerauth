# 0.31.0 — Breaking: effect-actions 0.23.0 peers, redacted provider headers, trimming contract schemas, `ProviderUnavailable.of`, and tagged development-issuer errors

Breaking for applications on effect-actions 0.21 or 0.22, for TypeScript code that implements or reads the administration contract's `Owner`, that encodes resource or key input through the contract, that builds `ProviderUnavailable` with a cause, that calls the SDK's `Credentials.list()`, or that catches or fakes what `@gjermundgaraba/clankerauth-dev` returns. The database, the configuration, the issuer's HTTP and MCP wire forms and the SDK's verification are as in 0.30.0, so an application on SDK 0.30.0 verifies against a 0.31.0 issuer and the reverse. Every package and the server go to 0.31.0 to keep one version across the release.

## Upgrading

1. **effect-actions 0.23.0.** The SDK's optional and the administration contract's `@gjermundgaraba/effect-actions` peer is `^0.23.0`, formerly `^0.21.0`; the two ranges do not overlap, so an application on 0.21 or 0.22 moves to 0.23 with them. The `effect` peers are unchanged. effect-actions 0.22.0 and 0.23.0 break `ActionDurableObject.Alarm.set`, which now keeps the earliest time it is given, `ActionDurableObject.layerStubClient`, which takes a function returning the stub, and the reading of a SEP-3415 `-32023` error from a server of your own. None of them touches what clankerauth exports; the effect-actions changelog says how to migrate code that uses them.
2. **Provider headers.** `Owner.providerHeaders` yields `Redacted<Headers>`, formerly `Headers`. Unwrap it with `Redacted.value` where the provider takes it, and build it with `Redacted.make`.
3. **Trimming input schemas.** `ResourceInput`'s `identifier`, `name` and `scopes`, and the key name of `ApiKeyInput` and `ApiKeyUpdate`, are `Schema.Trim`: decoding trims them, and encoding refuses a value with surrounding whitespace. A client that encodes through the contract trims first, as the dashboard does. A request sent as JSON is unaffected: the issuer trims it on decoding, as it trimmed before.
4. **`ProviderUnavailable` with a cause.** Its constructor takes only `{ operation }`. Build one with a diagnostic cause as `ProviderUnavailable.of(operation, cause)`, formerly `new ProviderUnavailable({ operation, cause })`. The cause stays non-enumerable and off the wire.
5. **`Credentials.list` is an Effect.** The `/credentials` entry's `list` is the Effect itself, formerly a function returning it: write `yield* Credentials.list` for `yield* Credentials.list()`.
6. **Development issuer errors.** `startDisposableIssuer` and a refused `apiKey` reject with `ProvisioningError`, and a refused `ownerSession` or `ownerToken` with `ForwardAuthError`, formerly a plain `Error` with the same message. Both are exported, and each one's `_tag` is its name.
7. **Development issuer type.** `DisposableIssuer` declares `apiKey`, `ownerSession`, `ownerToken` and `close` as properties rather than methods, so a hand-written stand-in is checked against them strictly rather than bivariantly.

## Administration contract

- The `@gjermundgaraba/effect-actions` peer is `^0.23.0`.
- `Owner.providerHeaders` is `Effect<Redacted<Headers>, InternalServerError, Scope>`.
- `ResourceInput` and the key name trim on decoding. A resource's name and a key's name need one character after trimming, and a key's name at most 100 after trimming. Their JSON Schema, in the OpenAPI document and the MCP tool schemas, describes the wire form, a plain string, so it no longer carries the non-space pattern of a name or the pattern of a scope. The issuer refuses the same input as before, with the same messages.

## SDK

- The optional `@gjermundgaraba/effect-actions` peer is `^0.23.0`.
- `ProviderUnavailable.of(operation, cause)` builds the error with a diagnostic cause. The constructor takes `{ operation }`.
- `/credentials`' `list` is an Effect value rather than a function.
- The `/testing` entry's `startFakeIssuer` throws a `TypeError` when it cannot bind a port, formerly a plain `Error`.
- The `/effect-actions` entry's `Resource.verificationDeadline` is the five seconds a `Resource` gives each verification before failing it as `ProviderUnavailable`.

## Issuer

- Built on effect-actions 0.23.0.
- Built on the new contract. It no longer trims resource and key input itself, since the contract's decoding does.

## CLI and development package

- Built on effect-actions 0.23.0. Each carries its own copy, so installing it needs nothing new.
- Built on the new contract.
- `startDisposableIssuer` decodes its `resources` through the contract's `ResourceInput`, so their names and scopes are trimmed and checked as the dashboard's are. An invalid one rejects the start with `ProvisioningError`.
- `ProvisioningError` and `ForwardAuthError` are exported from the package root.
- The `/edge` entry's `reserveLoopbackPort` throws a `TypeError` when it cannot bind a port, formerly a plain `Error`.
