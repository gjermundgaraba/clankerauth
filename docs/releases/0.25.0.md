# 0.25.0 — Breaking: Effect 4.0 peers, pixel-paper 0.15.0, and `login` opens the browser

The dashboard moves to pixel-paper 0.15.0, and `clankerauth login` opens its approval page in the browser. The SDK and the administration contract take Effect 4.0 alone as their peer. The issuer's endpoints, its errors, the database, the SDK's API and its effect-actions peer are as in 0.24.0. Every package and the server go to 0.25.0 to keep one version across the release.

## Upgrading

1. **Effect 4.0.** `@gjermundgaraba/clankerauth-sdk` and `@gjermundgaraba/clankerauth-admin-api` peer `effect` `~4.0.4`, narrowed from `^4.0.4`: 4.0.4 or a later 4.0 patch, and no 4.1. Both use Effect's HTTP modules, which Effect's stability policy lets a minor release break, and effect-actions takes the same range. A program on Effect 4.0 changes nothing.

## Dashboard

- The sign-in, setup and editor forms are pixel-paper form cards: one busy state holds the submit button, the close glyph, cancel and the fields while a form sends, and focus moves to the submit button as it does.
- A dialog whose change is being saved stays open on Escape, a press on the veil and cancel until the issuer answers, so a refusal lands where it was asked for. A save the issuer does not answer within 20 seconds gives up with "The issuer did not answer in time. Check whether the change was made before trying again.", and the dialog can be left again.
- Fragment links and announcements use pixel-paper's shipped Commands.

## CLI

- `login` opens the approval page in the browser, and still prints its URL for a terminal with no browser to open, such as over SSH; `--no-browser` only prints it.

## SDK and administration contract

- The `effect` peer is `~4.0.4`, formerly `^4.0.4`; their APIs are unchanged.

## Development package

- Unchanged; it embeds the 0.25.0 dashboard.
