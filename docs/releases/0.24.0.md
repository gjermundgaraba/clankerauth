# 0.24.0 — Breaking: sign-ins to any application, `putResource`, and effect-actions 0.18.0

The `clankerauth` command signs in to any application that publishes its resource, and programs
take their tokens from the SDK's new `/credentials`, which the command is built on. Resources
are written with one action, `putResource`, beside a new `getResource`, and the administration
contract is published as `@gjermundgaraba/clankerauth-admin-api`. Every package moves to
effect-actions 0.18.0. Resource servers on SDK 0.23 verify against a 0.24 issuer unchanged, and
the reverse.

## Upgrading

1. **Sign the 0.23 command out first.** 0.24 keeps sign-ins in `sign-ins.json` and does not read
   0.23's `credentials.json`, so a sign-in left there keeps its refresh token live on the issuer.
   Before installing the new command, run `npx @gjermundgaraba/clankerauth@0.23.1 logout`, which
   revokes every sign-in and deletes the file; or revoke the command's connections from the
   dashboard and delete `~/.config/clankerauth/credentials.json`. Then `clankerauth login` again.
2. **Upgrade the issuer before what calls it.** A 0.23 issuer answers `putResource` and
   `getResource` with 404, so deploy the issuer first, then any tool that writes resources, then
   the command.
3. **Rewrite scripts that call the command:**

   | 0.23                                                   | 0.24                                          |
   | ------------------------------------------------------ | --------------------------------------------- |
   | `create-resource`, `update-resource`                   | `put-resource`, the same flags                |
   | `login <issuer> --resource <identifier> --scope <...>` | `login <application URL>`, `--scope` optional |
   | `token --resource <identifier>`                        | `token <URL under the resource>`              |
   | `logout --resource <identifier>`                       | `logout <URL under the resource>`             |

4. **effect-actions 0.18.0.** An application that uses the SDK's `/session` or `/effect-actions`
   entry points, or the administration contract, installs `@gjermundgaraba/effect-actions`
   `0.18.0`. Its own breaking changes are in its changelog; the one most programs meet is that
   `ActionCli.remote` and `remoteCommand` take the client their commands call as `client`.

## The `clankerauth` command

- `login <url>` signs in to the resource `url` identifies, read from its
  `/.well-known/oauth-protected-resource`: the issuer's origin publishes administration, and an
  application's URL its own resource. The issuer is the one the resource names, so sign-ins to
  several issuers are kept side by side.
- Each sign-in registers its own native client, asks for every scope the resource publishes
  unless `--scope` names fewer, and adds `offline_access`, alone for a resource publishing no
  scopes. A `login` replacing a sign-in revokes the one it replaces.
- `token [url]` and `logout [url]` act on the sign-in whose resource holds the URL, the most
  specific when several do; without one, `token` prints administration's and `logout` signs out
  of every sign-in.
- Administration commands use the administration sign-in, the one at `CLANKERAUTH_URL` when
  there are several, and send a current token with each request, refreshed as it expires.
- The sign-ins are in `~/.config/clankerauth/sign-ins.json`. Every change holds the file's lock,
  so commands and programs running at once refresh an expired sign-in once.
- `get-resource` and `put-resource` replace `create-resource` and `update-resource`.
- The command needs an issuer at 0.24.0 or later.

## SDK

- New `@gjermundgaraba/clankerauth-sdk/credentials`, Node only: `token({ url, token? })` gives a
  program its bearer token from the owner's sign-in, or from the environment when it gives one;
  `authorizing` is the same as an effect-actions client's `transformClient`, typed with
  `SignInRequired` and `TokenUnavailable`; and `signIn`, `signOut` and `list` manage the
  sign-ins the command shares with every program.
- The SDK now depends on `oauth4webapi` and `proper-lockfile`, which only `/credentials` loads.
- The optional `@gjermundgaraba/effect-actions` peer is `^0.18.0`.

## Administration contract

- Published as `@gjermundgaraba/clankerauth-admin-api`, formerly the private
  `@clankerauth/admin-api`: every owner action, its schemas, errors and HTTP bindings. Its
  version follows the issuer's.
- `putResource` creates a resource, or updates the one with its identifier, to exactly the name
  and scopes given, answering `{ resource, created }` with 200. It replaces `createResource`,
  which answered 201, and `updateResource`, which failed `ResourceNotFound` for a missing one.
  The administration resource is still refused with `InvalidInput`.
- `getResource` reads one resource by identifier, or fails `ResourceNotFound`.
- The MCP tools follow: `getResource` and `putResource` replace `createResource` and
  `updateResource`.

## Dashboard

- Adding a resource whose identifier is already listed is refused in the form, which names the
  resource to edit instead; saving one says "Resource saved.", added or edited.

## Development package

- Each start sets every resource given to its name and scopes, where it created only the ones
  missing, so a changed `resources` applies when a `dataDir` is reused. Client access and keys
  are kept.
