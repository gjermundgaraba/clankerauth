# 0.35.0 — Breaking: effect-actions 0.31 peer, and a listed client's own type in the administration contract

The SDK's optional effect-actions peer and the administration contract's effect-actions peer move from `^0.30.0` to `^0.31.0`. The administration contract gives the client listing its own `ClientSummary`, and `Client` no longer carries `onboarding` or `blocked`. The Effect peer remains `~4.1.1`, but effect-actions 0.31 requires Effect 4.1.3 or a later 4.1 patch. The issuer's HTTP wire form is unchanged: it already sent both fields on listed clients only. The database, the configuration and the SDK's verification are as in 0.34.0. Every published package and the issuer move to 0.35.0 together.

## Upgrading

1. **effect-actions 0.31 and Effect 4.1.3.** Install `@gjermundgaraba/effect-actions` 0.31 alongside the SDK's `/session` or `/effect-actions` entry points or the administration contract, with Effect 4.1.3 or a later 4.1 patch, which effect-actions 0.31 requires. effect-actions 0.31 changes nothing clankerauth exports; its changelog lists what it changes.
2. **`onboarding` and `blocked` belong to listed clients.** Read them from `listClients`'s `clients`, now `ClientSummary`, where both are required. A create, update or rotate result never carried them, and its type now says so.

## SDK

- The optional `@gjermundgaraba/effect-actions` peer is `^0.31.0`.

## Administration contract

- The `@gjermundgaraba/effect-actions` peer is `^0.31.0`.
- `ClientSummary` is `Client` with `onboarding` (`"managed" | "dcr" | "cimd"`) and `blocked` required; `ClientListResult.clients` lists it.
- `Client` drops the optional `onboarding` and `blocked`.

## Issuer, CLI and development package

- Built on Effect 4.1.3 and effect-actions 0.31.0. The CLI and development package carry their own copy.

## Dashboard

- Adding a resource no longer refuses an identifier the listing holds: like `putResource` everywhere else, it updates that resource. Saving says "Resource created." or "Resource updated.", from what `putResource` reports.
