# 0.35.0 — Breaking: a listed client's own type in the administration contract

The administration contract gives the client listing its own `ClientSummary`, and `Client` no longer carries `onboarding` or `blocked`. The issuer's HTTP wire form is unchanged: it already sent both fields on listed clients only. The database, the configuration and the SDK's verification are as in 0.34.0. Every published package and the issuer move to 0.35.0 together.

## Upgrading

1. **`onboarding` and `blocked` belong to listed clients.** Read them from `listClients`'s `clients`, now `ClientSummary`, where both are required. A create, update or rotate result never carried them, and its type now says so.

## Administration contract

- `ClientSummary` is `Client` with `onboarding` (`"managed" | "dcr" | "cimd"`) and `blocked` required; `ClientListResult.clients` lists it.
- `Client` drops the optional `onboarding` and `blocked`.
