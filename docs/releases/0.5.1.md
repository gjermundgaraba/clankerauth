# 0.5.1 — forward auth in the disposable issuer

`@gjermundgaraba/clankerauth-dev` could not serve forward auth: it hard-coded no
cookie domain, and since 0.5.0 the forward-auth routes are served only when one
is set.

- `startDisposableIssuer` takes `cookieDomain`, such as `notes.localhost`. The
  issuer is then `http://auth.<cookieDomain>:<port>` on the same loopback
  listener, `/forward-auth`, `/forward-auth/continue` and `/forward-auth/logout`
  are served, and the forward cookie is shared with every host under the domain.
  Browsers and Node resolve `.localhost` names to loopback without a hosts-file
  entry.
- Without `cookieDomain` nothing changes: the issuer stays
  `http://127.0.0.1:<port>` and the forward-auth routes answer `404`.
- The disposable issuer's settings now pass the server's own validation, so an
  unusable cookie domain fails at startup with the server's message.

`@gjermundgaraba/clankerauth-sdk` and the server are 0.5.1 with no changes, to
keep one version across the release.

## Correction

`GET /forward-auth/logout?rd=<url outside the cookie domain>` answers 302 to
`/login`, not 400. The 400 belongs to `/forward-auth/continue`, which has nowhere
to send the browser after sign-in; logout ends the session first and then falls
back to the login page. The behaviour has been this since 0.5.0 and is pinned by
`apps/server/tests/forward-auth.test.ts`.
