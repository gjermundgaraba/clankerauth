# 0.15.0 — A warning for a resource reached at another host

Not breaking. The issuer, its endpoints and the key list format are unchanged, so an application
on SDK 0.15.0 verifies against a 0.14.0 issuer and the reverse. The SDK, the development package
and the server go to 0.15.0 to keep one version across the release.

## SDK

- A resource's listener that publishes discovery logs one warning the first time an
  authenticated request reaches it at another host than its `publicUrl`. An OAuth client
  refuses metadata naming another resource than the one it reached (RFC 9728), so such a
  `publicUrl` fails every OAuth login while API keys keep working. The warning refuses nothing,
  since a proxy may rewrite the host; a listener with `discovery: false` never logs it.
- The README and `Options` say which URL `publicUrl` is: where the listener that publishes
  discovery is reached. A listener beside it with `discovery: false` takes that same URL, not its
  own address, and two listeners with different scopes are one resource in the dashboard,
  declared twice in the application.

## Issuer and development package

- No changes beyond the version. The development package embeds the 0.15.0 server.
