# 0.17.0 — The CLI signs in to any resource and prints its tokens

Not breaking. Only the CLI changes: the issuer, the SDK and the development package behave
as in 0.16.0, and go to 0.17.0 to keep one version across the release.

## CLI

- `clankerauth login <url> --resource <identifier> --scope <scopes>` signs in to one of the
  issuer's resources instead of administration, with its own consent and refresh token. It
  is kept beside the sign-in to administration, and beside one per other resource.
- `clankerauth token [--resource <identifier>]` prints a current access token for a resource
  signed in to, administration by default, and nothing else, refreshing it first when it has
  expired. Another command or a script takes its bearer token from there instead of keeping
  an API key.
- `clankerauth logout --resource <identifier>` revokes and forgets that sign-in alone;
  `logout` without it still revokes every one and deletes the file.
- The credentials file keeps a list of sign-ins. A file 0.16.0 wrote is read as it is, and
  written in the new form the next time a command refreshes or signs in.
