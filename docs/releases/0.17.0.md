# 0.17.0 — The CLI signs in to any resource and prints its tokens

Breaking for the CLI alone: its flags and its credentials file change, so sign in again after upgrading it. The issuer, the SDK and the development package behave as in 0.16.0, and go to 0.17.0 to keep one version across the release.

## Upgrade

Run `clankerauth login <url>` once after upgrading: the file 0.16.0 wrote counts as signed out, and the new sign-in replaces it. Its refresh token is not revoked and expires within 30 days. In scripts, replace `login --read-only` with `login --scope clankerauth:read`, and drop `--no-browser`.

## CLI

- `clankerauth login <url> --resource <identifier> --scope <scopes>` signs in to one of the issuer's resources instead of administration, with its own consent and refresh token. It is kept beside the sign-in to administration, and beside one per other resource.
- `clankerauth token [--resource <identifier>]` prints a current access token for a resource signed in to, administration by default, and nothing else, refreshing it first when it has expired. Another command or a script takes its bearer token from there instead of keeping an API key.
- `clankerauth logout --resource <identifier>` revokes and forgets that sign-in alone; `logout` without it still revokes every one and deletes the file.
- `--scope` replaces `--read-only`: administration's default is `clankerauth:read clankerauth:write`, and `--scope clankerauth:read` lists alone.
- `login` no longer opens a browser: it prints the approval URL, and `--browser` and `--no-browser` are gone.
- `login` checks discovery as RFC 9728 and RFC 8414 require: the URL given must be the issuer's own origin, its `CLANKERAUTH_BASE_URL`, and the metadata must name the issuer it came from. Another address for the same issuer, such as `http://` for an `https://` one, is refused instead of signing in under a name later commands do not find.
- Signing in to another issuer than the kept one revokes and forgets the kept sign-ins first; 0.16.0 dropped them without revoking.
- A credentials file the CLI cannot read counts as signed out: `login` replaces it and `logout` deletes it.
- The OAuth exchanges are `oauth4webapi`'s, a new dependency.
- The callback page no longer says the sign-in succeeded before it has: it sends the owner back to the terminal, which reports the outcome.
