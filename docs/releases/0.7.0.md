# 0.7.0 — one public URL, one scope object, one 403

Breaking for both packages and the server. Both `@gjermundgaraba/clankerauth-sdk`
and `@gjermundgaraba/clankerauth-dev` are prepared at 0.7.0. There are no live
installations to migrate.

0.6.0 moved the resource rule here but left every application restating it: the
origin root written by hand, a scope list and a `requiredScopes` list and a
`writeScope`, two 403s that meant different things, an `exemptPaths` argument that
was always `["/healthz"]`, and a `whoami` group, a `Principal` schema and a
sign-out URL copied into all five. This release deletes the restating.

## Resource

- `Resource.make` takes `publicUrl` and one scope object:

  ```ts
  Resource.make({
    issuer,
    publicUrl: new URL("https://notes.internal"),
    scopes: { read: "notes:read", write: "notes:write" },
  });
  ```

  The identifier is `new URL("/", publicUrl).href`, so the origin root is derived
  rather than written, any path on the URL is discarded, and the canonical-identifier
  check the SDK used to run has nothing left to refuse. `resource` is still exposed
  for a caller that needs the string.

- `scopes.read` is required at verification, so a read needs no further check.
  `scopes.write` is what an `access: "write"` action additionally needs. A
  single-scope application passes only `read`, and then `authorize` passes
  everything, as `writeScope`-less resources did before.
- `admit(authorization, access)` requires `access`. A socket that is a read says
  so, instead of inheriting a default. `Resource.middleware` admits at `"read"`
  and leaves the action's own `access` to the hook.
- `resource.session` implements the SDK's own `session` group from the verified
  credential, so an application deletes its `whoami` handler along with its
  contract. Bind it beside the application group: `Http.layer(app, resource.session)`.
- Gone: `resource.headers()`, `resource.challenge()`, `resource.writeScope`,
  `encodeError`, and the root re-export of `Principal`. The verified credential's
  type is `Verifier.Principal`. A resource is now
  `{ verifier, discovery, admit, authorize, session, resource, issuer }`.

## One 403

- `Forbidden` is deleted. A credential that is valid but lacks a scope is
  `InsufficientScope`, which names only the missing scope. A credential that is
  not this resource's at all is `Unauthorized`: a wrong audience, and an API key
  the issuer answers `403 "No access to this Resource"` for, are the same case
  from the resource's side.
- `authenticationErrors` is now the whole list — `Unauthorized`,
  `InsufficientScope`, `RateLimited`, `ProviderUnavailable` — and is exactly what
  a surface declares in its `errors`. `admissionErrors` is deleted, because it
  had become the same list.
- The missing-scope refusal from verification names the scope the same way the
  hook does, so the challenge is `error="insufficient_scope", scope="<missing>"`
  wherever it comes from.

## Browser entry points

- `@gjermundgaraba/clankerauth-sdk/errors` holds the error schemas and
  `authenticationErrors`. The root no longer exports them, so a shared contract
  cannot import them from a place that would pull verification into a browser
  bundle.
- `@gjermundgaraba/clankerauth-sdk/session` holds the `session` action group, the
  `Principal` schema `{ subject, issuer, scopes }`, and
  `signOutUrl(issuer, returnTo)`, which builds the issuer's
  `/forward-auth/logout?rd=…`. All five applications had written these.
- The package declares `"sideEffects": false`. Its smoke test bundles both entries
  for the browser and fails if `jose`, `verifyApiKey` or `at+jwt` reaches the
  output, by module graph and by text.

## Request policy

- `exemptPaths` is deleted. `/healthz` is the single fixed exemption, because a
  container probe reaches the app on its bind address and carries neither header,
  and no application had a second one. `allowedOrigins` stays, for a desktop
  shell's private renderer scheme.
- `RequestPolicy.make` stays standalone and keeps taking `publicUrl`. Reaching it
  through the resource would have forced the effect-actions peer on a caller that
  only wants the policy, and would have made two applications thread the resource
  into the module that builds it.

## Dev

- `backend` and `socketPaths` become one option:
  `sockets: { backend, paths }`. Omit it and the edge takes no upgrades at all,
  which is what four of the five development edges want.
- A refusal is relayed as the issuer wrote it: status, `Location`, body and
  content type. A script that is not signed in now reads
  `{"error":"unauthenticated"}` instead of an empty 401.
- An upgrade whose client socket is already destroyed is dropped before the
  backend handshake, rather than opening two halves of a connection nobody holds.
- New `@gjermundgaraba/clankerauth-dev/testing`: `startFakeIssuer({ resource,
scopes })` serves JWKS and `POST /api/issuer/verifyApiKey` and nothing else,
  signing with a real EdDSA key so tokens still travel the resource server's own
  verifier. `sign(claims?, typ?)`, `apiKey(scopes, resource?)`, `revoke(key)`,
  `fail(status?)` and `verifications()`. Four repositories had copied this.
- The two `pathOf` helpers stay separate: the policy's reads a request target
  that may be an absolute URL, the edge's reads a path that never is.

## Server

- The dashboard refuses a resource identifier that is not already in canonical URL
  form (`new URL(id).href === id`). A client sends back exactly what discovery
  published, so an identifier the client would rewrite could never match.
- The issuer's own administration resource is `<baseURL>/mcp`, not an origin root:
  `/` is the dashboard, authenticated by the owner's session cookie and never an
  OAuth audience. It therefore stops using the SDK's `Resource`, which is now
  origin-root by construction, and builds discovery and admission from
  `Verifier.make` and effect-actions' `Authentication` in
  `apps/server/src/administration-resource.ts`. One middleware now verifies the
  token and resolves the owner, and MCP refusals are the issuer's own
  `{ _tag, error }` vocabulary — the same one every other route here answers with.
  Statuses and `WWW-Authenticate` challenges are unchanged.

## Migration

- `Resource.make({ issuer, resource: new URL("/", publicUrl).href, scopes: [...],
requiredScopes: [READ], writeScope: WRITE })` becomes
  `Resource.make({ issuer, publicUrl, scopes: { read: READ, write: WRITE } })`.
- Import errors from `/errors`, and replace `admissionErrors` with
  `authenticationErrors`. Delete every `Forbidden` branch: a client sees
  `Unauthorized` where it used to see `Forbidden`, and `InsufficientScope` where
  it used to see the scope 403.
- Delete the local `whoami` action, the local `Principal` schema and the local
  sign-out URL helper; import `Session`, `Principal` and `signOutUrl` from
  `/session` and serve `resource.session`.
- Bind the hook on each adapter rather than on `implement`, as effect-actions
  0.4.0 requires: `Http.layer({ before: resource.authorize }, app,
resource.session)` and `ActionMcp.layerHttp({ …, errors: authenticationErrors,
before: resource.authorize }, app)`. The group no longer declares
  `InsufficientScope`; the surface does, through `authenticationErrors`.
- Pass the access to `admit`. Delete `exemptPaths` arguments. Replace `backend`
  and `socketPaths` with `sockets`.
- Delete copied signing issuer fixtures in favour of `/testing`.
