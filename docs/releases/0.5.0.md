# 0.5.0 — forward auth

This is a breaking issuer and SDK release. Both
`@gjermundgaraba/clankerauth-sdk` and `@gjermundgaraba/clankerauth-dev`
are prepared at 0.5.0. There are no live installations to migrate.

## Forward auth

- New `GET /forward-auth?resource=<identifier>` for Caddy `forward_auth` and
  Traefik `forwardAuth`. A browser holding a valid forward cookie gets a
  fifteen-minute access token for the named resource in an `Authorization`
  header; otherwise it is redirected through
  `/forward-auth/continue?rd=<original url>`, which signs the owner in only when
  the issuer has no session, and back to the page it asked for.
  Missing forwarded headers or a host outside the cookie domain are `400`; an
  unknown resource or the built-in administration resource is `403`.
- The forward cookie is the owner's session cookie value sealed under the server
  secret, set by `/forward-auth/continue` on `AUTH_COOKIE_DOMAIN`. The issuer
  session cookie itself stays on the issuer host, so apps behind the proxy never
  hold it. The forward cookie resolves to the live session and is revoked by
  sign-out.
- New `GET /forward-auth/logout?rd=<url>` ends the owner session, clears both
  cookies, and redirects to an allowed destination, or to `/login`.
- Tokens carry `client_id: "forward-auth"` and all of the resource's scopes.
  Resource servers verify them with the existing SDK verifier; administration
  MCP never accepts them.
- New optional `AUTH_COOKIE_DOMAIN`: a bare parent domain of the issuer host
  that the forward cookie is shared with.
- The dashboard login page follows a same-origin `rd` after sign-in.
- The server package and its MCP server version are 0.5.0 as well.

## Removed

- OpenID Connect: the `openid`, `profile` and `email` scopes, ID tokens,
  `/oauth2/userinfo` and `/.well-known/openid-configuration`. Access tokens name
  exactly the requested resource. Clients requesting `openid` receive
  `invalid_scope`. Discovery is the OAuth document at
  `/.well-known/oauth-authorization-server/api/auth`, which the MCP client SDK
  tries first.
- SDK browser sessions: `BrowserSession`, `SessionStore`, `BrowserActions`, the
  `/browser-api` subpath, the `browser` option of `Resource.middleware`, and the
  `StoreError` and `InvalidRequest` errors. The SDK is verification only; the
  `oauth4webapi` dependency is gone.

## Not in this release

- clankerpedia still targets the retired `@gjermundgaraba/clankerauth-node`
  package and OIDC UserInfo; its migration to the SDK and forward auth is a
  separate change.
