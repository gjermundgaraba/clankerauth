# 0.14.0 — Effect 4.0.2 and effect-actions 0.11.0

Breaking for applications on Effect 4.0.0 or 4.0.1, or on effect-actions 0.10.0. The issuer's
endpoints and the key list format are unchanged, so an application on SDK 0.14.0 verifies
against a 0.13.0 issuer and the reverse. The SDK, the development package and the server go to
0.14.0 to keep one version across the release.

## Upgrade

Install `effect` and `@effect/platform-node` `4.0.2` or later, and
`@gjermundgaraba/effect-actions` `0.11.0` if you use the `/session` or `/effect-actions` entry
points. effect-actions 0.11.0 requires Effect `~4.0.2`; its changelog lists the rest of its
changes, none of which affected this repository.

## SDK

- The `effect` peer is `^4.0.2`, and the optional `@gjermundgaraba/effect-actions` peer
  `^0.11.0`.
- A JWKS read that every waiting caller gave up on, at `Resource`'s five-second deadline, is
  dropped rather than held: the next verification reads again, with a deadline of its own. In
  0.13.0 it answered `ProviderUnavailable` for five seconds first. Effect 4.0.2's
  `Effect.cachedWithTTL` no longer keeps an interrupted run. A failed read still holds off the
  next one for five seconds, and concurrent verifications still share one read, which a caller
  giving up no longer interrupts while another still waits on it.
- A key list read every waiting caller gave up on is likewise dropped, and the next key reads
  the list again. A list read that fails or takes longer than three seconds still holds off
  the next one for five seconds while the held list decides.

## Issuer and development package

- Built on Effect 4.0.2 and effect-actions 0.11.0. Effect 4.0.2's HTTP tracing follows
  OpenTelemetry conventions: the issuer's server spans are named for the method (`POST`, was
  `http.server POST`), and a 4xx response no longer fails its span. Update dashboards and
  alerts that match the old names or statuses.
- The development package embeds the 0.14.0 server.
