# 0.7.2 — effect-actions 0.5.0

No behaviour changes in either package or in the server. Both
`@gjermundgaraba/clankerauth-sdk` and `@gjermundgaraba/clankerauth-dev` go to
0.7.2 to keep one version across the release.

- The peer and catalog pin moves to `@gjermundgaraba/effect-actions` 0.5.0. Its
  adapter layers now take the implementations first, as a collection, with
  options second and optional where nothing needs binding. An application on
  this SDK updates its own bindings when it upgrades:

  ```ts
  // 0.7.1, on effect-actions 0.4.1
  Http.layer({ before: notes.authorize }, app, notes.session);
  ActionMcp.layerHttp({ name, version, path, protocols, before: notes.authorize }, app);

  // 0.7.2, on effect-actions 0.5.0
  Http.layer([app, notes.session], { before: notes.authorize });
  ActionMcp.layerHttp([app], { name, version, path, protocols, before: notes.authorize });
  ```

  `resource.authorize`, `resource.session`, `Resource.middleware` and every
  other export keep their shape.

- The pre-handler hook now runs after the input is decoded, on every surface.
  `resource.authorize` reads only the action's `access` and the principal, so
  its decisions are the same; a request with an invalid body is now refused by
  the schema before the hook sees it.
- `ActionHttp` no longer marks its responses `Cache-Control: no-store`. Every
  route wrapped in `Resource.middleware` still carries it, because
  `Authentication.middleware` sets the header itself, so nothing this SDK
  authenticates is answered differently. A route an application serves with
  `Http.layer` and no authentication middleware now has whatever cache policy
  the host sets, which was always the host's to set.
- The issuer's own responses are unchanged: the server applies its cache and
  security headers globally and never relied on the adapter's.

## Documentation

- The SDK README's binding snippets use the 0.5.0 argument order, and its
  description of a hook refusal names `Resource.middleware`, not effect-actions,
  as the source of `Cache-Control: no-store`.
