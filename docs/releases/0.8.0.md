# 0.8.0 — MCP 2026-07-28 only, on effect-actions 0.7.0

Breaking for both packages and the server. Both `@gjermundgaraba/clankerauth-sdk`
and `@gjermundgaraba/clankerauth-dev` are prepared at 0.8.0, on Effect
`4.0.0-rc.117` and `@gjermundgaraba/effect-actions` 0.7.0.

## MCP is 2026-07-28 only

- Administration MCP serves only the stateless **2026-07-28** revision. A client
  of 2025-11-25, 2025-06-18 or 2025-03-26 opens with `initialize` and is refused
  with HTTP 400 and a JSON-RPC error. There is no session, so there is no
  `initialize` handshake and no `Mcp-Session-Id`. Pin the official client with
  `versionNegotiation: { mode: { pin: "2026-07-28" } }`.
- The `/mcp` CORS preflight allows only `POST` and the 2026-07-28 request
  headers. `GET` and `DELETE` preflights, and preflights that ask for
  `Mcp-Session-Id` or `Last-Event-ID`, are refused with 403. A response exposes
  exactly `WWW-Authenticate` and `Mcp-Protocol-Version`.
- 2026-07-28 has no cancellation over HTTP: without a session,
  `notifications/cancelled` interrupts nothing. A tool call is part of its POST,
  which runs under the server's uninterruptible route middleware like every
  other request. On the session-based revisions in 0.7.2, a client could cancel
  an owner action while a provider call was in flight. A caller that disconnects
  does not stop its call either, so a create or rotate may complete without the
  caller seeing its one-time secret: rotate the client secret, or replace the API
  key, to recover.

## SDK: effect-actions peer `^0.7.0`

- The optional peer on `@gjermundgaraba/effect-actions` is `^0.7.0`, not an
  exact pin, so a later 0.7.x satisfies it without an SDK release.
- The SDK's published declarations are built against effect-actions 0.7.0,
  which drops a type parameter from `Action.Action`. SDK 0.7.2's declarations
  do not resolve under effect-actions 0.7.0 and, with `skipLibCheck`, silently
  degrade to `any`. Upgrade to SDK 0.8.0 and effect-actions 0.7.0 together.
- effect-actions 0.6.0 removes the `protocols` option. An application on this
  SDK deletes it from its own binding when it upgrades:

  ```ts
  // 0.7.2, on effect-actions 0.5.0
  ActionMcp.layerHttp([app], { name, version, path, protocols, errors, before: notes.authorize });

  // 0.8.0, on effect-actions 0.7.0
  ActionMcp.layerHttp([app], { name, version, path, errors, before: notes.authorize });
  ```

  Its `schemaError` policies, OpenAPI route, Promise clients and MCP test
  helpers move to the 0.6.0 APIs, and its actions and Promise clients to the
  0.7.0 ones (no `http` action option, no `token` client option, no explicit
  `Action.make` type arguments), as the effect-actions CHANGELOG describes.
  `Resource`, `resource.authorize`, `resource.session`, `Resource.middleware`
  and every other SDK export keep their shape.

- The SDK's `effect` dependency is `4.0.0-rc.117`. Install the same version in
  the application.

## Server

- A key whose stored permissions no longer decode now fails listing and
  verification with the contract's `InternalServerError` (500, JSON body), not an
  empty 500.
- The administration OpenAPI route, the groups' schema-error policy and the
  dashboard's API client now come from effect-actions (`Http.openApi`,
  `{ invalid, internal }` and `ActionHttpClient.promise`). `GET /openapi.json`
  stays where it was, and no action's HTTP answer changes. The administration
  tools' input and output schemas are also unchanged under rc.117, which changed
  how MCP output schemas are generated.

## Development package

- A start that fails after binding its port, for example on an invalid
  `cookieDomain`, frees the port and removes its directory before rejecting, so
  there is nothing to close.

## Documentation

- The root README says MCP is 2026-07-28 only and points at these notes.
- `docs/provider-integration.md` states the shutdown rule once, under "Shutdown": whatever
  serves the issuer must wait for in-flight requests before the issuer's scope closes, as
  `NodeHttpServer` and the development package do and `HttpRouter.toWebHandler`'s `dispose` does not.
- The SDK README's MCP binding has no `protocols`, and its install lines name
  Effect `4.0.0-rc.117`.
