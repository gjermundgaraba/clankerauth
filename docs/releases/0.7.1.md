# 0.7.1 — tests and documentation for what 0.7.0 already does

No behaviour changes in either package or in the server. Both
`@gjermundgaraba/clankerauth-sdk` and `@gjermundgaraba/clankerauth-dev` go to
0.7.1 to keep one version across the release.

- The peer and catalog pin moves to `@gjermundgaraba/effect-actions` 0.4.1, which
  refuses an `access` that is neither `"read"` nor `"write"` at `Action.make` and
  restores `ActionCli.command`'s typed error channel. Nothing this package calls
  changed shape.
- A resource built with `apiKeys: false` is now pinned by a test: a key-shaped
  bearer is refused as `Unauthorized` on the prefix alone, and the issuer's
  verification endpoint is never called. The option reaches the verifier through
  `Resource.make`, which had no test of its own.
- Both package smoke tests assert that every `exports` entry has the declaration
  file it names. The development package shipped one build without `edge.d.ts`
  and `testing.d.ts`, and nothing failed until a consumer imported them.

## Documentation

- The SDK README's surface and scope-enforcement snippets import what they use:
  `authenticationErrors`, `ActionHttp` and `Session`.
- The resource examples in the root README and in the development package's
  README are origin roots, as 0.7.0 requires. `https://notes.internal/mcp` as a
  token audience or a `verifyApiKey` body was the 0.6.0 shape; an application
  registers `https://notes.internal/` and that one resource covers `/api`,
  `/mcp` and its sockets. The issuer's own administration resource is still
  `<AUTH_BASE_URL>/mcp` and is unaffected.
- The root README points at the 0.7.0 notes as the breaking ones to read before
  upgrading.
